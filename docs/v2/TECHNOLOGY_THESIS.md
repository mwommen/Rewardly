# Technology Thesis

## Valuable Capabilities

- Wallet-first enforcement.
- Rule precedence.
- Benefit eligibility and wallet state.
- Merchant identity and category confidence.
- Versioned benefit registry.
- Decision explanation and warnings.
- Deterministic validation and regression tests.

## Differentiated Capabilities

- One owned-card recommendation with evidence.
- Traceable rule selection and rejected-rule reasons.
- Confidence based on merchant, rule, wallet state, and freshness.
- Scenario-based validation before release.

## Defensible Over Time

Assumption: defensibility will come less from code alone and more from data operations, partner feedback loops, regression corpus, merchant/benefit edge-case knowledge, and trusted decision-quality processes.

## Commodity Capabilities

- Express routing.
- Basic API keys.
- Dashboard CRUD.
- Generic analytics plumbing.
- Static docs.

## Necessary Infrastructure

- Tenant isolation.
- Versioned API.
- Rate limiting.
- Idempotency.
- Observability.
- Security reviews.

## Moat Discipline

Do not call the Chrome extension a moat. The engine, data quality process, decision trace, and validation corpus are the defensible seeds.
